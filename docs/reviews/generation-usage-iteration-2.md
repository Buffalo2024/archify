## Evidence protocol

Repeat the three pinned projects and original Workflow requests: SkillRoster,
Pixelle-Video, and Kanban. Assign separate Sol 6.1 medium Agents to frozen main,
dev, and candidate packages. Each receives one fresh draft, two focused
repairs, and at most one extra retry justified by new measured evidence. Give
no old candidate, implementation answer, or cross-arm feedback to generators.
Interview the same Agent only after its result is saved.

Record public commands, source/package identities, input snapshots, exits,
durations, gate receipts, and post-run feedback. Do not collect private
reasoning. Serialize browser-capable commands and report lock waits separately.
Run the existing 93 immutable inputs across all comparison packages, keeping
unsupported modes distinct from failed delivery. Compare the 43 historical
successes for acceptance and normalized SVG stability, then run focused,
repository, browser, and extracted-package checks appropriate to the final
change. Verify semantics when a repair edits the candidate.

Complete this iteration with independent code review, inspectable HTML and
execution evidence, and an explicit list of remaining failures. A small number
of selected difficult runs is not a general success-rate estimate. Static
acceptance, complete finalize, and perceptual review remain separate claims.

Local evidence lives in `layout-followup/usage-iteration-2` under this task's
visualization directory. No live installation, publication, push, or merge is

### Implemented behavior

- Workflow v2 can recover implicit labels against the complete scene after an
  initial failure, while preserving explicit label positions and route/node
  geometry. The successful initial path and v1 output remain unchanged.
- A failed scene can offer coordinated label/connected-waypoint edits only
  after ordinary compiler replay succeeds. `verifiedRepairs` verifies the
  compiler scope; it does not certify full delivery or browser acceptance.
  The mixed failure path is bounded by six plans and four layout feedback
  attempts per plan. Author edits are proposals, never silently applied.
- Workflow context-readability failures can identify the exact source/width
  paths, fitted font and conditional minimum width. Advice stays explicitly
  unverified until complete finalize. Canonical font fitting is reused.
- Diagnostic dependencies load only on applicable Workflow failures, so an
  incomplete installation can still run doctor and unrelated isolated CLI
  paths do not require font modules at startup.

### Actual use and compatibility

All nine fresh runs (three projects, three arms) failed at validation. None
produced an accepted HTML. All execution records and nine later interviews are
retained. The semantic audit also found omitted business exits and non-geometric
repair edits in some runs; these are not evidence of geometry-only improvement.

The 93 frozen historical inputs show no new recovery relative to the previous
candidate: 51 pass and 42 fail. All 51 successful normalized SVGs remain
identical, including the 43 original successes across ten diagram modes.
Separately, 18 fresh first/final drafts replayed on four packages all failed.
The final dependency-loading correction was replayed on all 111 inputs: zero
status changes, 51 identical successful SVGs, and unchanged comparable font
budget diagnostics. Package and input hashes remained stable.

A separate handoff experiment gave three Agents the same historical Kanban
failure draft. Main and dev still failed after two repairs. The real-use
candidate passed complete finalize after one edit, `autogit.width: 168 -> 172`,
selected by its Agent from the new diagnostic without a supplied width hint.
All nodes, edges, text, sources and the nine-step mainPath remain exactly equal.
This is an existing-draft layout repair, not fresh generation or proof of full
business coverage: the frozen starting draft already omitted the edge from
the interrupted-session exit to Done. Three post-result interviews are saved.

Two minimal label-recovery reproductions also passed complete delivery. The
final extracted package independently re-finalized these two examples and the
repaired Kanban draft. All three passed validation, delivery, strict checking
and real Chrome checking; their complete HTML and SVG bytes match the prior
tested artifacts. They do not establish recovery of the failed real Pixelle or
fresh project drafts.

### Tests, review and observed cost

The broad `npm test` run at `bd5a6ccf` recorded 2,704 passes, three failures and
92 optional browser skips. The three failures exposed eager imports breaking
incomplete doctor and two isolated output-path race fixtures. After repair,
the complete affected CLI/output-path/font/loading files passed 171/171 with
no skips. The earlier full command was not rerun or relabeled as a final-head
pass. Its unaffected coverage is reused with exact revisions and file hashes.

The maintained browser gate passed 291/291 without skips at `bd5a6ccf`. At the
final runtime, the affected finalize/readability browser files passed 2/2;
package/identity checks passed 56 with two explicit toolchain/platform skips.
Reusing the broader browser result is supported by unchanged Viewer/compiler
bytes, the 111-input replay and three final-package full deliveries. Independent
font, routing, CLI-loading and semantic reviews are preserved separately.

Root inspected the Kanban artifact at 1366x900 in both themes, the two minimal
reproductions at 1440x900 in both themes, and the report at desktop and 390px.
The return corridor and labels have no observed overlap; Kanban context text
remains small at 100%. Manual camera checks confirm 75% overview and a 25%
minimum. This is a narrow repair, not a claim of broad visual improvement.

Sequential public CLI measurements used official Node 22, one warm-up and five
measurements per arm/input, after other tests completed. Final versus previous
candidate medians were 488.5 versus 493.7 ms for one successful input, 321.3
versus 283.2 ms for a still-failing explicit-pin input, and 355.9 versus 350.6 ms
for a still-failing composition input. The explicit-pin failure adds 38.1 ms;
the other ranges overlap. These small samples exclude browser, lock waiting
and model time and do not establish general performance.

### Remaining target and evidence

The iteration has a useful local diagnostic/repair result, but does not improve
independent complex-Workflow delivery. Remaining failures involve interacting
route corridors, endpoint constraints and label/node changes. The next bounded
experiment should start with a real failed frozen candidate, jointly propose
connection-neighborhood geometry edits, and require complete delivery before
broadening. Preserve semantics and explicit intent; do not relax gates or
count semantic deletions as recovery.
